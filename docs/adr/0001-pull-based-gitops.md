# ADR-0001: Pull-based GitOps с записью digest из CI

**Статус:** accepted
**Дата:** 2026-10-25

## Контекст

Нужен механизм доставки для Docker Swarm, аналогичный ArgoCD: состояние кластера должно соответствовать декларации в git, а ручные изменения — откатываться.

## Решение

WormCD работает по pull-модели: control plane сам читает git и реконсилит кластеры. CI собирает образ, пушит его в registry и коммитит immutable digest в deploy-репозиторий. Контроллер не собирает образы и не следит за registry.

## Следствия

- git — единственный источник истины; rollback = revert коммита или применение сохранённой ревизии.
- Дрейф устраняется автоматически при `selfHeal`.
- Нужен CI-шаг write-back в deploy-репо и права на него.
- Задержка между сборкой и деплоем определяется коммитом и интервалом опроса/webhook, а не push-запросом.

## Альтернативы

- **Push-based**: CI вызывает API WormCD. Проще, но нет самовосстановления и git перестаёт быть истиной.
- **Контроллер следит за registry**: удобно, но неявные деплои и потеря аудируемости.
