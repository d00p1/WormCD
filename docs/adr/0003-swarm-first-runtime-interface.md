# ADR-0003: Swarm-first с интерфейсом Runtime

**Статус:** accepted
**Дата:** 2026-10-25

## Контекст

Цель — Docker Swarm и vanilla Docker. Реализовывать оба рантайма сразу дорого, но жёсткая привязка к Swarm потребует переписывания ядра.

## Решение

В v0 поддерживается только Swarm, но всё применение идёт через интерфейс `Runtime` (`Inspect`, `Apply`, `Prune`, `Health`). Ядро работает с нормализованной моделью `Desired`/`Observed` и не импортирует Swarm-специфичные типы. Реализация vanilla Docker добавляется как второй `Runtime`.

В M0 интерфейс содержит только `Kind` и `Inspect`; `Apply`, `Prune` и `Health` добавляются в M1, когда появляется право менять кластер.

## Следствия

- Дублирование абстракции на старте, пока реализация одна.
- Все Swarm-особенности (configs/secrets, update-order, labels) инкапсулированы в `internal/runtime/swarm`.
- Тесты ядра (diff, plan, policy) не требуют Docker.

## Альтернативы

- **Только Swarm без абстракции**: быстрее, но второй рантайм = переписывание.
- **Оба рантайма сразу**: дольше до рабочего v0.
