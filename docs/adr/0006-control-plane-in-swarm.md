# ADR-0006: Control plane внутри Swarm-кластера

**Статус:** accepted
**Дата:** 2026-10-25

## Контекст

Control plane должен работать постоянно, иметь persistent storage и доступ к Docker API всех кластеров. Варианты: отдельная VM, сервис в одном из Swarm-кластеров, локальный запуск.

## Решение

Control plane запускается Swarm-сервисом с одной репликой в управляющем кластере. SQLite и git-кэш лежат на persistent volume, привязанном к узлу. Управляющий кластер подключается через socket, остальные — по mTLS.

## Следствия

- Не нужна отдельная VM; инфраструктура переиспользуется.
- Падение управляющего кластера останавливает управление всеми кластерами — принятая цена v0.
- Нет HA: одна реплика, локальный volume.
- Обновление самого WormCD до M5 — вручную, вне WormCD, чтобы не создавать цикл перезапуска посреди sync.
- Нужен смонтированный Docker socket, что расширяет права сервиса.

## Альтернативы

- **Отдельная VM**: устойчивее и не зависит от кластера, но +1 хост.
- **Локальный запуск**: годится только для M0.
